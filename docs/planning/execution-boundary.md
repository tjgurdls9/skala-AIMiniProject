# 서비스 구현과 로컬 모델 실행 검증의 경계

2026-10-21 15:30 KST. 사용자 정정에 따른 우선 기준이다. 기존 작업 지시의 ‘카공지도 지원 공백을 CLI가 직접 구현’하는 해석을 철회한다.

## 제품과 검증 과제

제품은 사용자가 **앱에 요청을 입력하면 로컬 모델들이 도구를 사용해 개발 전주기를 수행하는 서비스**다. Codex·Claude 작업 세션은 이 서비스의 실행기·도구·격리·문맥·승인·평가·사무실 화면을 구현한다. 카공지도는 서비스 안에서 수행할 검증 과제다. 카공지도 전용 기능을 작업 세션이 미리 구현해 모델에 주는 것은 자율 개발 검증이 아니다.

| 주체 | 역할 |
|---|---|
| 작업 세션 | 자동화 서비스 자체의 공통 기반 구현·결함 수정, 실행 관찰·근거 대조 |
| 앱 내부 로컬 모델/에이전트 | 요청 해석·기획·Phase/Sprint/작업 분해·앱 코드/인프라 생성·도구 호출·검토·수정 계획 |
| 신뢰 실행기/도구 | 모델의 허용된 제안을 검증·실행하고 원장/결과를 보존. 임의 권한 상승 없음 |
| 사용자 | 기획·범위 조정·외부 자격/키·중요 동의·정확한 배포 대상 승인 |

고정 스택이나 빈 시작 프로젝트는 사전에 정의할 수 있다. 검증 요청을 본 뒤 정답 기능·카페 검색 API·DB·지도 UI를 작업 세션이 시작 프로젝트에 채워 넣고 모델 성과로 취급하면 안 된다. 범용 자격증명 보관/네트워크 제한 도구를 만드는 일과, 검증 앱의 특정 검색·추천 로직을 대신 만드는 일을 구분한다.

## 검증 절차

1. 서비스 커밋·모델/설정·도구·시작 프로젝트·검증 기준을 고정하고 기록한다.
2. 사용자의 요청은 앱 경로로 전달한다. CLI가 전송을 대행했다면 주체와 대행 사실을 기록한다. 사용자의 기획·배포 결정을 합성하지 않는다.
3. 요청별 계획·코드 변경·도구 호출은 앱 내부 에이전트와 실행기를 거친다. 작업 세션은 생성 앱의 파일/패치/답안을 직접 공급하지 않는다.
4. 실패하면 입력/실패/산출물과 막힌 단계를 그대로 보존한다. 서비스 결함, 모델 판단 실패, 권한/환경 미준비는 근거가 있을 때 구분한다.
5. 서비스의 공통 결함을 고쳐야 하면 해당 실행의 평가를 종료하고 별도 서비스 변경으로 처리한다. 수정한 커밋으로 새 검증 실행을 시작한다. 과거 실패는 보존한다.
6. 중간 개입이 있는 실행은 개입 내역과 함께 개발/통합 확인 자료로 남긴다. 개입 없는 자율 개발 완주 근거로 사용하지 않는다. 단위 검사 수·직접 API 연결 성공·문서/시안 작성은 앱 생성 완주 점수가 아니다.

## 현재 기록의 판정

- 기존 카공지도 실행 `846eed645f8245909d72cff799099d0b`에는 작업 세션의 전용 템플릿/어댑터 추가와 실행 중 서비스 수정이 개입됐다. **로컬 모델 자율 개발 수용은 미검증**이다. 기획 생성·일부 근거 표시·중지/재개·기록 이동 등 개별 관찰은 그 범위로 보존한다.
- `templates/cafemap-v1/**`, `backend/{kakao,geoapify}.py`, `backend/templates.py`의 프로필 분기, `infra/checks/validate_cafemap.py` 등은 출처·역할 재검토 대상이다. 전부 삭제하거나 전부 범용 기반으로 재명명하지 않는다. 앱 정답 로직/공통 보안 도구/독립 평가 도구가 섞여 있으므로 파일·변경 단위로 대조한다.
- 서울시청 Geoapify 검색은 작업 세션이 수행한 수동 연결 검사다. 로컬 모델의 도구 선택·앱 구현·사용자 위치 동의·검토·배포 성과가 아니다.
- 기존 코드·실패 원장·커밋·비공개 키는 보존한다. 이 문서 정정은 코드 삭제·롤백·재실행·외부 작업 승인이 아니다.
