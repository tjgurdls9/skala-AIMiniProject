# 구현·제출 계획

상태: 구현 순서와 완료 조건을 정의한다. Codex·Claude CLI의 구현 R&R은 확정됐으며 일부 백엔드·런타임 파일이 존재한다. 파일 존재만으로 아래 작업의 완료를 인정하지 않는다. 실제 준비·변경·확인 결과는 각 담당의 인계 기록으로 확인한다.

## 1. 첫 완주의 범위 제안

자동화 제품이 생성할 첫 앱은 **합성 CSV 기반 고객 문의 분류·처리 대시보드**로 제안한다. SKALA와 연결되는 데이터 처리·웹 구현·검증·보안·운영을 보여주면서 외부 비공개 데이터 없이 준비할 수 있다. 이 도메인은 아직 사용자 확정이 아니다.

생성 앱의 기획 승인용 AC 초안:

1. 고정 합성 CSV를 읽고 필수 열·자료형 오류를 명확히 반환한다. 실제 고객 개인정보를 입력하지 않는다.
2. 문의 목록·상세·분류/처리 상태 변경을 저장하고 새로고침 뒤에도 유지한다.
3. 분류별 집계가 실제 데이터·필터와 일치한다.
4. AI 기능을 선택하면 공유된 무료 모델 경로로 분류 제안을 만들고 실패/불확실성을 표시한다. 이를 검증되지 않은 자동 정답으로 저장하지 않는다. Data 처리만으로 시작할지 승인 때 결정한다.
5. 입력·API·화면·비밀·의존성 검사 근거와 Docker Compose 실행·health·배포/복구 절차를 제공한다.

도메인 분류 정확도 목표는 표본과 평가 기준 없이 임의 퍼센트를 약속하지 않는다. AI 정확도·속도와 전주기 자동화의 완주 성공은 따로 설명한다. 첫 앱을 CRUD로 줄여도 승인·독립 검토·수정·Git·배포 단계를 생략하지 않는다.

## 2. 실행 조건 확인 — D0

추가 질문으로 기획을 막지 않고 기본값을 마련했다. 다만 실제 부작용 전에는 다음을 확인한다.

| 항목 | 현재 상태 | 확인 후 결정 |
|---|---|---|
| 장비 | 사용자 제공 사양 확정 | OS/Ollama·Docker·여유 메모리·디스크 실제 상태 |
| 모델 | 소형 Qwen/DeepSeek 후보, 미설치/미실측 | 정확 태그·라이선스·JSON/tool 호환·문맥·자원 |
| 무료 API | 공식 제공 조건 조사, 계정별 자격 미확인 | 무료 잔여/만료·대상 모델·과금 차단. 불명확하면 비활성 |
| OpenAI 키 | 보유 사실만 전달받음 | 읽거나 출력하지 않음. 기본 실행 경로에서 제외 |
| 코드 실행기 | 신규 제품 실행기 없음 | 허용 작업 디렉터리·컨테이너·네트워크·중지 정책 |
| GitHub | 비공개 원격 생성, 로컬 Git/worktree 준비 미완료 | Codex가 기존 변경을 보존하며 준비. 실제 상태는 [공통 준비 인계](../handoffs/codex.md) 참조 |
| 배포 | 실제 호스트 미정 | 기존 무료/테스트 환경 하나. 인증·노출·자동 배포 트리거·복구 |
| 제출 | PDF는 Git/보고서 URL 요구 | 별도 평가 장비/네트워크 조건은 미확인. 재생을 기본 열람 경로로 준비 |

모델 후보를 비교하는 준비는 필수 호환성 확인이지 보너스용 Before/After 비교군 구축이 아니다. 모델 다운로드는 별도 구현 착수 때 수행한다. 네트워크·다운로드·로컬 전력·호스팅 비용이 모두 0이라고 약속하지 않는다.

## 3. 구현 작업 묶음

제품이 실행 중 나누는 Phase/Sprint와, 이 제품 자체를 만드는 아래 D 작업은 다른 계층이다. 먼저 순서대로 작은 동작을 완성하고, 계약 이후 독립 작업만 병행한다. 각 단계는 이전 결과로 돌아갈 수 있도록 작업 브랜치·커밋·DB 마이그레이션과 샘플 기록을 보존한다.

| 작업 | 의존성 | 산출물·완료 조건 | 되돌릴 때 |
|---|---|---|---|
| D0 준비 | 없음 | 위 환경·무료·모델·저장소·배포 대상 상태표. 불가 항목은 LIVE 비활성 | 다운로드/설정만 제거, 사용자 기존 환경 유지 |
| D1 계약·저장 | D0 | 프로토콜·도메인 모델·SQLite 원장·명세 버전·아티팩트 경계. AC05/11/24 기반 | DB 백업과 이전 계약 유지, 파괴적 자동 이전 금지 |
| D2 실행 뼈대 | D1 | 짧은 역할 실행·영속 큐·중지/재개·더미 도구가 아닌 상태 검증 가능한 도구 경계. AC07/22 | 외부 부작용 없는 이전 실행기로 전환 |
| D3 모델·문맥 | D2 | Ollama 어댑터·허용 공급자 정책·구조화 출력·필수 조건 패킷. AC11–15 | 로컬 공급자만 유지, 외부 경로 비활성 |
| D4 문서 검색·MCP | D1, D3 | 허용 코퍼스·역할 필터·출처 근거·Tool/Resource/Prompt. AC20 | 원문 유지, 인덱스만 재생성 가능 |

| D6 독립 검토 | D5 | 서로 격리된 검증·보안·변조 불가 보고서·실패→수정. AC09/10 | 출시 게이트 닫고 이전 검토 구조 보존 |
| D7 사무실 화면 | D1·D2, 이후 D5·D6 연결 | 프로젝트 지도·선택 Sprint 장면·근거·승인·모바일·모션·보조 관련도. AC17/19 | 장면 비활성, 동등한 DOM 업무 목록 유지 |
| D8 프리뷰·변경 | D5–7 | 격리 프리뷰·피드백 원문·구현/기획 재진입·옛 승인 무효. AC06 | 새 후보 폐기, 마지막 유효 후보 유지 |
| D9 Git·배포 | D6·D8·실제 대상 준비 | 같은 커밋 푸시·검토 이미지 digest 유지·복구 manifest·배포 승인·중복 방지·상태 확인. AC04/05 | 승인된 이전 이미지·설정으로 복구, DB 호환 별도 확인 |
| D10 완주·복구 근거 | D9 | 작은 앱 실제 한 번 완주·한 번 수정·중지/재시작·검토 차단 증거. AC01/16/22 | 실제 실패도 기록 보존, 보고서에 한계 명시 |
| D11 제출·설명 | D10 | 키 없는 실제 기록 재생·README·모델/실행기 안내·Git/보고서 URL·발표 | 공개에서 비밀·민감 자료 제거, 재생 근거 무결성 유지 |

라이브러리 버전은 이 문서의 현재성 추정으로 정하지 않고 착수 시 호환 버전을 lock한다. 구현 시 테스트 작성·실행은 승인된 작업 범위에 따라 진행하며 현재 기획 단계에서는 실행하지 않았다.

**먼저 연결할 최소 세로 흐름:** 요청→명세→기획 승인→파일 생성 작업→독립 검토 결과→프리뷰→배포 승인→허용된 프리뷰 호스트. 캐릭터 디테일을 늘리기 전에 이 흐름과 실제 오류·중지·재개를 연결한다. 단, 접근성·권한 검증·비밀 차단은 후순위로 미루지 않는다.

## 4. 병행 가능한 작업과 순차 경계

D1 계약 이후 D7의 화면 골격을 준비할 수 있다. D5의 Front/Back은 API 계약·데이터 스키마가 고정된 뒤 각 공간에서 병행한다. D6의 검증·보안은 같은 통합 후보 생성 뒤 독립 실행한다. D9는 검토·사용자 프리뷰·실제 배포 대상이 준비되기 전 진행하지 않는다.

사용자가 연 Codex·Claude CLI가 [협업 프로토콜](collaboration.md)의 R&R에 따라 구현한다. 별도 ChatGPT 대화는 관제탑이며 두 CLI를 자동 기동·재개하지 않는다. agy는 이번 구현에 배정하지 않고, 추가 서브에이전트를 자동 기동하지 않는다. 제품 내부 멀티 에이전트 기능 구현은 이 개발 세션 운영과 구분한다.

## 5. 모델·검색·도구 선정 기준

| 영역 | 최초 후보 | 선정에 필요한 근거 |
|---|---|---|
| 생성·판단 | Ollama의 Qwen 소형 / DeepSeek 소형 | 무료·정확 태그·라이선스·메모리·한국어·패치/JSON 품질 |
| 임베딩 | 로컬 Qwen3-Embedding 0.6B | 생성 모델과의 자원 경합·문서 검색 동작 |
| 오케스트레이션 | LangGraph+영속 큐 | 수업 연계·짧은 실행/중단 복구·숨은 반복 상한 없음 |
| 저장·검색 | SQLite·로컬 청크/벡터 | 메타데이터·역할 필터·작은 코퍼스, 별도 서버 필요성 |
| HTTP·UI | FastAPI·Vue·SSE·2D Canvas | 베이스/참고 재사용·계약 일치·접근성 |
| 구현 공간 | Git worktree 또는 별도 checkout·Docker Compose | 쓰기 소유권·비권한 실행·호스트 비밀 격리 |
| 기능 검증 | pytest·Playwright 후보 | 생성 스택과 실제 필요한 범위에 맞는 최소 검사 |
| 보안 | Semgrep·Gitleaks·Trivy 후보 | 코드·비밀·의존성/이미지 범위, 룰·DB·라이선스 확인 |
| 관찰 | 로컬 실행 원장 기본, LangSmith 선택 | 비밀 제거·무료 한도·외부 전송 동의/조건 |

카탈로그 전체 감사·설치는 하지 않는다. 후보의 라이선스와 공급망은 실제 도입 전에 확인한다. MCP는 모든 shell 명령을 통째로 노출하는 장치로 사용하지 않는다.

## 6. 제출 패키지

- Git 저장소: 제품 코드·lock 파일·설정 예시·설계·생성 예제. 키·모델 가중치·개인 데이터·거대한 캐시는 제외한다.
- README: 키 없는 열람 → Ollama LIVE → 조건부 무료 API LIVE를 구분한다. 프론트만으로 코드 실행이 되지 않는다는 조건을 명시한다.
- 실제 실행 기록: 공개 이벤트·명세 버전·코드/검토/배포 아티팩트 해시·공급자/모델/런타임 버전·기록 시각. secret 제거 후 원본과 공개본의 관계를 설명한다.
- 결과 보고서: 문제 → 구현 포인트 → 실제 동작 근거 → 한계·트레이드오프 → 후속 개선. 비교 미실시를 명시하며 가짜 수치를 채우지 않는다.
- 발표: 요청 입력, 사무실 작업 분담, 독립 검사에서 반려, 수정 프리뷰, 승인된 배포와 재생 동선을 보여준다. 데모에서 실제 실패하면 실패·한계를 그대로 설명한다.

PDF의 기술 항목은 Multi-Agent·MCP·RAG·DI·LangSmith·모듈화·단위 테스트 등을 충분히 고려했는지 본다. 전부를 이름만 추가하는 것으로 점수를 보장하지 않는다. 이 설계는 역할 분담·MCP 3기능·기술 문서 RAG·주입 가능한 모델/도구·역할 모듈·검증 근거로 설명한다. LangSmith는 무료/보안 조건이 맞을 때의 선택 항목이다.

PDF의 Day3 13시·17시30분 일정은 과제 자료 기준이다. 현재 남은 실제 시간이 확인되지 않아 이 범위를 3일 안에 완성한다고 약속하지 않는다. 시간이 부족하면 추가 테마·범용 스택·보조 판단 고도화부터 미루고 전주기 핵심과 검토·승인 경계를 지킨다.

## 7. 후속 실험과 열린 결정

비교군·Before/After·여러 모델 성능 순위·다중 테마·다중 사용자·다중 배포 대상은 후속이다. 장기 운영 전에는 데이터 보존/삭제, 원격 접근 인증, 백업, 동시 프로젝트 수, 무료 자격 만료 시 재개 운영을 정한다. 지금 필요한 제품 기획은 마련됐으며, 실제 환경 확인이 필요한 항목을 완료했다고 표시하지 않는다.
