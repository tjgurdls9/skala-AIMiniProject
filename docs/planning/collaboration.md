# 구현 협업 프로토콜

상태: 구현 협업 준비. **관제탑에서 GitHub 비공개 저장소를 생성했다. 로컬 `.git` 쓰기 제한으로 Git/worktree 초기화는 Codex CLI에 인계한다.** 실제 준비 상태는 [Codex 인계](../handoffs/codex.md)가 소유한다. 제품 내부의 멀티 에이전트 런타임은 [아키텍처](architecture.md)에서 별도로 정의한다.

## 1. 사용 전 필수 순서

사용자가 정한 R26에 따라 구현에서 assistant 서브에이전트를 쓰기로 하면 다음을 완료한 뒤 spawn한다.

1. 사용자에게 사용할 의도·맡길 범위·통합 책임을 알린다.
2. 기존 Git 상태·원격·GitHub 인증·업로드 범위를 확인한다. 인증 오류를 우회하거나 새 비밀을 요구하는 흐름을 자동 진행하지 않는다.
3. 새 프로젝트 GitHub 저장소를 준비한다. 기본 제안은 private이며 평가자가 접근할 수 있게 별도 조정한다. 공개 전환·외부 공유는 의도와 제출 조건에 맞춰 결정한다.
4. PDF·기존 예제·개인 데이터·secret·모델 파일을 통째로 올리지 않는다. 필요한 새 코드·문서·라이선스가 확인된 참고만 포함한다. 비밀값을 출력하지 않고 제외 정책을 먼저 작성한다.
5. 이 프로토콜의 확정본·요구사항·계약·작업 분할을 해당 저장소의 커밋으로 기록한다. 원격에 프로토콜이 존재하는 상태를 확인한다.
6. 작업 ID·소유 경로·계약 버전·기준 커밋·완료 조건을 할당하고 서브에이전트를 시작한다.

선행 조건을 충족하지 못하면 서브를 먼저 띄우지 않는다. 주 에이전트가 독립적으로 가능한 작업을 계속한다. 명령 도구의 자동 승인 심사가 거절하면 작업과 거절 이유를 사용자에게 설명하고 허용 범위 안에서 진행한다.

## 2. 할당 형식

각 작업에는 `작업 ID / 목표 / 관련 R·AC / 기준 커밋 / 명세·계약 버전 / 읽을 입력 / 쓸 경로 / 금지 경로 / 선행 작업 / 산출물 / 확인 방법 / 통합 담당`을 적는다.

서브에이전트는 작업을 임의 확대하거나 기준을 완화하지 않는다. 공유 계약·lock 파일·DB 마이그레이션·전역 스타일·실행 진입점은 한 소유자만 변경한다. 필요한 변경은 소유자에게 요청하고 합의된 계약 커밋 이후 진행한다.

## 3. 작업 공간과 Git

- 기본 브랜치 직접 작업 대신 작업별 branch와 worktree/checkout을 쓴다. 세부 선택은 도구·권한에 맞춘다.
- 한 공간의 타 에이전트 미완성 diff를 자신의 결과에 섞지 않는다. 기존 사용자 변경을 정리한다는 이유로 되돌리거나 삭제하지 않는다.
- 서브는 자신에게 할당된 변경만 만든다. 통합 담당만 공유 기준에 병합한다. force push·기본 브랜치 rewrite·무단 배포는 하지 않는다.
- 보고에는 변경 커밋 또는 정확 diff·아티팩트를 연결한다. “완료” 문장만으로 통합하지 않는다.
- 검증 명령 실행은 사용자 승인된 구현/검증 범위에 따른다. 미실행 결과를 실행 통과로 적지 않는다.

## 4. 독립 검토·통합

구현이 끝난 뒤 같은 후보에 검증·보안을 별도 입력·세션으로 배정한다. 두 검토에 builder 대화나 상대 미확정 보고서를 전달하지 않는다. 공유 모델을 쓰더라도 결과 입력을 섞지 않는다.

각 검토의 원본·근거를 보존한 뒤 주 에이전트가 종합한다. 충돌은 근거와 계약으로 해결하고 필요하면 수정 작업을 만든다. 통합 후 기준 커밋이 바뀌면 판정 유효성을 다시 확인한다. 발견한 실패를 문구로 지우고 통과시키지 않는다.

## 5. 결과 보고·다음 세션

보고는 `수행 내용 / 변경 파일·커밋 / 관련 AC와 증거 / 미실행·실패 / 남은 위험 / 다음 작업` 순으로 남긴다. secret·전체 환경변수·내부 사고 원문은 넣지 않는다.

다음 세션은 루트 기획 진입점→요구사항→현재 작업의 계약·기준 커밋→미해결 근거 순으로 읽는다. 대화 요약만 믿고 명세를 재구성하지 않는다. 팀 작업 상태는 실제 저장소의 단일 작업 목록에 기록하며 별도 문서마다 완료 여부를 복제하지 않는다.

## 6. Codex·Claude 병렬 구현 분담

사용자 요청에 따라 구현을 두 세션에 나눠 맡긴다. 전달할 프롬프트는 [Codex](../prompts/CODEX_IMPLEMENTATION.md), [Claude](../prompts/CLAUDE_IMPLEMENTATION.md)다. 구현 세션은 사용자가 직접 열며 관제탑이 자동 기동하거나 직접 메시지를 전송하지 않았다. 앞의 GitHub·프로토콜 선행 조건은 유지하며, 추가 서브에이전트를 자동 기동하지 않는다.

| 영역·예정 경로 | 변경 소유자 | 상대 세션의 경계 |
|---|---|---|
| `backend/**` | Codex | Claude는 읽기·요청만 |
| `runner/**`, `mcp/**`, `templates/**`, `knowledge/**` | Codex | 제품 내부 도구·생성 앱 템플릿·RAG 담당. Claude는 수정 안 함 |
| `infra/**`, `scripts/**`, `.github/**` | Codex | 루트 통합·배포·계약 생성 작업 담당 |
| `frontend/**` | Claude | UI·API 소비자·표시 상태·사무실 Canvas·타입 생성·프론트 의존성/lock 담당. Codex는 직접 덮어쓰지 않음 |
| `docs/planning/contracts.md`, `protocol.v1.schema.json`, 향후 HTTP 계약 | Codex 조율, 양쪽 영향 검토 | Claude는 필요를 요청하고 승인된 변경을 소비 |
| `frontend/src/generated/**` | Claude가 공유 계약에서 생성 | 수기 수정 금지. Codex는 계약 버전·커밋을 제공하고 프론트 파일은 수정하지 않음 |
| `frontend/src/examples/**` | Claude | 스키마를 따르는 명시적 합성 예시. 실제 기록으로 가장하지 않음 |
| 루트 `.gitignore`, `README.md`, 실행 구성·상태 문서 | Codex | Claude는 `frontend/README.md`에 사용법 작성 후 통합 요청 |
| `docs/handoffs/codex.md` | Codex | 결과·계약 답변·통합 기준 기록. Claude 읽기 전용 |
| `docs/handoffs/claude.md` | Claude | 결과·계약 요청·UI 인계 기록. Codex 읽기 전용 |
| 강의 PDF·`all_total_vue_student/**`·형제 참고 프로젝트 | 양쪽 읽기 전용 | 새 제품과 분리. 통째 복사·업로드하지 않음 |

위 경로는 구현할 때 만들 예정인 소유 경계이며 이미 존재하는 코드 구조가 아니다. 프론트는 `frontend/package.json`과 해당 lock, 백엔드는 `backend/` 내부 의존성 파일로 관리한다. 루트 공용 package/lock을 양쪽이 동시에 만들지 않는다. 소비자 타입 생성 도구·설정·출력은 Claude가 프론트 안에서 관리하고, Codex는 공통 계약의 버전과 호환성만 조율한다.

### 역할별 작업 범위

- Codex: D0–D6·D9 기반, D8 서버 동작, D10–D11 통합. 실행 원장·모델·ECC 문맥·RAG/MCP·격리 작업 공간·독립 검토 기능·Git/배포·복구·서버 권한을 구현한다.
- Claude: D7 전체, D8 프리뷰/수정 UI, D10–D11의 화면·프론트 사용법. 최초 요청·기획/배포 승인·프로젝트/Phase/Sprint/작업 지도·근거·오류·중지/재개·사무실 장면·보조 관련도 UI를 구현한다.
- 두 구현자의 인계 보고는 독립 검증·보안 판정을 대체하지 않는다. 제품 런타임의 validator/security 격리는 Codex가 구현하며, 자체 구현을 검토하는 개발 세션을 독립 심사자라고 부르지 않는다.

## 7. 동시 착수와 짧은 공통 준비

완전히 선행 작업이 없는 병렬 구현을 약속하지 않는다. Git 초기화·공유 계약 확정·작업 공간 분리만 Codex가 한 번 처리하고, 그 뒤에는 백엔드 완료를 기다리지 않고 양쪽이 진행한다.

1. Codex는 기존 변경과 GitHub 인증·원격을 확인하고, 필요한 저장소·초기 프로토콜 커밋·명시적 업로드 범위를 준비한다. 인증이 안 되면 결과를 설명하고, 선행 조건을 조용히 생략하지 않는다.
2. Codex는 기준 커밋에서 `work/codex-runtime`과 `work/claude-office` 브랜치 및 별도 worktree를 준비한다. 위치는 워크스페이스 안의 `.worktrees/codex-runtime`, `.worktrees/claude-office`를 기본으로 하되 실제 위치를 인계 파일에 기록한다. 기존 경로·브랜치를 무단 삭제/재사용하지 않는다. `.worktrees/`는 Git 업로드에서 제외한다.
3. Claude는 자신의 공간이 준비되기 전 문서·참고 화면을 읽고 구성안을 정리할 수 있다. 원본 작업 공간에서 먼저 코딩하거나 독자적으로 `git init/switch`하지 않는다. 준비 뒤 자기 공간에서만 수정한다.
4. 현재 JSON Schema의 Snapshot·Command·Event는 양쪽이 바로 읽을 수 있다. Claude는 이를 따른 로컬 예시·DOM UI·Canvas를 개발하고, Codex는 실행기·서버를 개발한다.
5. HTTP 생성 요청·runtime 응답·명령 접수 응답·오류 본문·SSE 최초 cursor·인증 방식 등 미확정 경계는 Codex가 D1에서 먼저 문서/기계 계약으로 확정한다. Claude는 이 부분만 연결을 보류하고 나머지 화면 작업을 계속한다.
6. API/계약 준비 신호와 기준 커밋을 Codex 인계에 남긴다. Claude는 그 기준을 명시 병합/반영하고 소비자 타입을 생성한 뒤 실제 API 어댑터를 연결한다. 예시 어댑터를 바꾸려고 UI를 전부 다시 만들지 않는 작은 경계만 둔다.
7. 최종 통합은 Codex가 맡는다. 필요할 때 상태·계약·통합 커밋을 교환하고, 기본 브랜치에서 동시 작업하지 않는다.

worktree가 나뉘면 수정 내용은 자동으로 공유되지 않는다. 서로의 승인된 커밋과 인계 파일을 읽기 전용으로 확인하고 필요한 커밋만 병합한다. 상대의 미완성 파일을 복사하거나 루트에서 `git switch`해 양쪽 작업 환경을 바꾸지 않는다. 임의 stash·reset·clean·force push는 금지한다.

프론트가 루트 명령으로 설치·빌드될 필요가 있으면 Codex가 루트 스크립트를, Claude가 프론트 명령을 맡고 경계만 맞춘다. 로컬 포트는 충돌을 확인해 Codex 인계에서 정하며, 남의 프로세스를 종료해 확보하지 않는다.

## 8. 계약 변경·인계 메시지

Claude는 자기 인계 파일에 `요청 ID / 필요한 사용자 동작 / 현재 계약의 부족 / 제안 입출력 / 호환성 영향 / 우회 가능한 UI 작업`을 남긴다. Codex는 자기 인계 파일에 `같은 요청 ID / 채택·보류·거절 이유 / 계약 버전·커밋 / 실제 지원 경로`로 답한다. Claude는 타입 재생성 결과를 자기 인계에 남긴다. 상대 파일을 수정하지 않는다.

별도 세션 사이의 자동 메시지 전송을 전제하지 않는다. 작업 묶음의 시작·종료와 연결 경계에서 상대 인계를 확인하고, 필요한 신호는 사용자가 각 세션에 전달할 수 있다. 인계 대기 동안 무관한 파일을 바꾸거나 무한 폴링하지 않는다.

각 인계는 기준 커밋·계약 SHA256·담당 작업·실제 변경 파일·실행/미실행 확인·남은 문제·다음 요청을 포함한다. 상태의 단일 원본은 Codex가 관리하는 구현 작업 목록이며 인계는 각자의 근거·요청이다. 문서 작성 완료를 기능 구현 완료로 승격하지 않는다.

## 9. 관제탑과 agy의 제한된 시험

사용자가 별도로 운영하는 ChatGPT 대화 세션이 관제탑이며, 이 문서·프롬프트를 전달받는 Codex CLI와 Claude CLI는 각각 구현 작업 세션이다. 관제탑은 요구사항·역할 경계·계약 충돌·인계·역할 확대와 통합 순서를 조율한다. 제품 코드 변경 소유권은 위 표대로 유지한다. 세션 간 전달은 사용자가 맡으며 자동 전송을 전제하지 않는다.

agy는 사용자 최종 결정에 따라 이번 구현에 배정하지 않는다. Infra는 Codex 담당이다. [AGY-TRIAL-001](agy-trial.md)과 `experiments/agy-infra-trial/`은 별도 합성 시험의 기록이며 실서비스 설정이 아니다. 시험 결과와 검토는 보존하되, 이 기록을 근거로 agy를 재기동하거나 제품 작업을 맡기지 않는다.

이 시험의 결과는 원격 저장소에 자동 반영하지 않는다. 독립 검증·보안 PASS나 Infra 소유권 이전도 자동으로 발생하지 않는다. 실제 모델/agent 호출은 준비 기록의 상태와 구분해 보고한다. 추가 agent의 자동 기동에는 기존 선행 조건이 그대로 적용된다.
