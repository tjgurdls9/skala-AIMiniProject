# 요구사항과 대화 반영표

기준일: 2026-10-20. 사용자 확정 조건과 설계자의 제안을 구분한다. ID는 후속 설계·구현·수용 시나리오의 연결점이다.

## 1. 제품 정의

대상은 작은 업무 서비스를 만들려는 개발자·팀장과 교육 평가자다. 요청을 전달한 뒤 개발 단계를 사람이 하나씩 중계하는 일을 줄이고, 중요한 결정은 사람이 하며, 무엇을 만들었고 왜 통과·반려됐는지 확인하게 한다.

최초 제공 범위 제안은 한 사용자, 프로젝트별 격리 공간, 한 저장소, 한 배포 대상, 작은 웹 업무 앱이다. 필요한 인프라·프론트·백엔드·AI/Data 작업을 의존성에 따라 수행한다. 모든 요청에 AI 기능이나 새 인프라를 억지로 추가하지 않는다.

성공은 승인한 인수 기준에 연결된 코드·실행 결과·독립 검토·Git 이력·배포 결과로 판단한다. 에이전트의 대화량이나 캐릭터 움직임은 완료 증거가 아니다.

## 3. 대화 순서에 따른 선택과 정정

| 흐름 | 검토·결정 | 현재 반영 |
|---|---|---|
| 시작 | Base 개선 vs 신규, PDF·코드 검토 요청 | 신규 선택. 베이스는 참고·부분 재사용 |
| 주제 탐색 | 스타트업 심사·주식 토론·TRPG 등 외부 답변 | 외부 답변의 수상작·순위·재사용률은 미검증으로 채택 안 함 |
| 도메인 적합성 | 엔터테인먼트 쏠림·SKALA 부적합 우려 | 실제 개발 생산성·검증·운영을 가치로 설정 |
| 기획 평가 | 기획 DB·최신/비공개 자료 제약으로 폐기 판단 | 독립 제품으로 부활 안 함. 자체 명세는 개발 전주기의 단계 |
| 공개 RAG | 오픈소스 RAG 활용 질문 | 기술 문서·저장소·결정 근거 검색. 없는 기획 DB 전제 안 함 |
| 전주기 | 아이디에이션→배포 원큐 제안 | 핵심 제품. 반복 중계를 줄이며 HITL은 유지 |
| 정체성 | Orchestrator와 닮았다는 지적 | 오케스트레이터임을 인정하고 별도 개발 |
| 단일 모델 | 별도 개발·단일 LLM 차별화 검토 | 이후 멀티 에이전트 요구로 대체. 가중치 공유와 단일 에이전트는 구분 |
| 비용 초안 | 테스트 Ollama·실전 OpenAI | 이후 무료 전용·모델 제한이 우선. 유료 기본안 철회 |
| HITL | 기획·배포 주요 결정에 동의 | 버전에 묶인 승인 게이트 |
| 속도 | Ollama/DeepSeek 멀티 에이전트로 빠르게 | 독립 작업 병행. 16GB 동시 추론 속도 보장 안 함 |
| 독립 검토 | 검증·보안은 폐쇄 독립 | 격리된 검토 라운드와 원본 보고서 |

| 수정 | 배포 전 구현 루프 필요 | 수정 Sprint, 영향 범위 재검토 |

## 4. 제안 기본값 — 사용자 확정 사실과 구분

| 항목 | 제안 | 이유·변경 가능성 |
|---|---|---|
| 첫 완주 앱 | 합성 CSV 기반 고객 문의 분류·처리 대시보드 | 개인정보 없이 Front/Back/Data 검증. 더 작은 CRUD로 조정 가능 |
| 서비스 | FastAPI+Vue+SQLite, 백엔드·작업 실행 프로세스 각 하나 | 강의 구조와 가까움. 다중 사용자 SaaS부터 만들지 않음 |
| 생성 앱 | FastAPI+Vue+SQLite+Docker Compose 템플릿 1종 | 자유 스택보다 실제 완주 가능성 우선 |
| 추론 | 소형 Qwen 양자화 후보, 추론 슬롯 1부터 | 최종 모델은 품질·메모리 확인 후 선택 |
| RAG | 로컬 문서 청크·SQLite 메타데이터·로컬 벡터 검색 | 별도 상시 검색 서버 없이 시작 |
| 배포 | 사전 지정한 프리뷰 호스트 1곳 | 유료 자원 자동 생성 방지. 실제 대상은 착수 시 확인 |
| 사용자 | 개인 운영자 1명 | 인증·권한 경계 유지. 조직 관리·결제 후순위 |

기획 승인에서 범위를 확정한다. 문서 작성으로 외부 배포·푸시·유료 인프라 생성이 승인되지 않는다.

## 5. 범위와 변경

첫 완주에는 실제 코드 변경·검증·보안 결과·사용자 수정 루프·Git 작업·승인된 배포가 필요하다. 기획서 생성이나 장면 연출만으로 완료하지 않는다.

테마 추가, 다중 사용자, 임의 언어·클라우드, 대규모 기존 저장소 개조, 비교군은 후속 범위다. 고위험 의료·금융 업무를 첫 데모로 택하지 않는다.

최신 사용자 지시가 이전 제안과 충돌하면 최신을 우선하고 원문·정정 이력을 보존한다. 승인 버전을 올리고 영향을 받는 작업·판정·배포 승인을 무효화한다. 에이전트가 구현 편의 때문에 AC를 완화할 수 없다.
