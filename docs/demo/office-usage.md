## 사무실 사용법

사무실은 요청 하나로 시작해 기획 승인, 구현, 독립 검토, 프리뷰, 사람 확인까지를 건물 단면 화면으로 보여 주는 프론트엔드다. 화면은 서버가 보낸 기록만 보여 주고 스스로 판정하지 않는다.

### 실행 순서

API(8000)를 먼저 띄우고, 그다음 Vite(5173)를 띄운다. 프론트는 `/api`를 8000으로 프록시한다.

```bash
# 1) API: 런타임 문서의 실행 방법을 따른다(포트 127.0.0.1:8000)
# 2) 프론트
cd frontend
npm install
npm run dev        # http://127.0.0.1:5173
```

브라우저에서 `http://127.0.0.1:5173`을 연다. API가 없으면 시작 화면 입력창 아래에 "서버에 연결하지 못했습니다"가 뜬다. 합성 예시로 자동 전환하지 않는다.

### 시작 화면

- "무엇을 만들까요?" 아래 입력창에 만들 서비스를 쓰고 **Enter**(줄바꿈 Shift+Enter)를 누른다. 원문은 그대로 보존되고 기획 승인 전에는 구현이 시작되지 않는다.
- 입력창 아래 안내가 경고색이면 LIVE 실행을 시작할 수 없는 상태다. 아래 "실행 가능성 · 실제 기록 재생 · 합성 예시" 링크에서 모델·실행기 상태와 사유를 본다.
- 같은 링크에서 **실제 기록 재생**(읽기 전용)과 **합성 예시**(실제 실행 아님)를 연다. 오른쪽 위 버튼으로 화면 밝기와 장면 모션을 바꾼다.

### 사무실 화면

- 5층 건물 단면이다. 왼쪽 엘리베이터에서 층(1F 기획 … 5F 프리뷰·출시)을 옮긴다. 점이 있는 층은 알림이나 진행이 있는 층이다.
- 오른쪽 위 알림의 "열기"는 지금 사람이 해야 할 결정(기획 승인, 프리뷰 확인, 배포 대상)을 연다.
- 화면 아래 "상세 작업 정보 ↓"로 내려가면 Sprint 보드, 작업 목록, 사건 기록, 출시·복구, 기록 내보내기가 있다.
- 작업자나 작업을 누르면 오른쪽 **근거 패널**에 명세·AC·아티팩트·최근 사건·두 보고서가 열린다. 기획안과 보고서 원문은 아티팩트를 눌러 본다.
- 주소창의 `?run=<id>`가 실행 위치다. 새로고침이나 주소 공유로 같은 실행에 돌아온다.

### 승인 화면

- **기획 승인**: 대안, 작업 분해, AC별 점검, 지원 공백을 읽고 "이 기획으로 구현 시작" 또는 "수정 요청(거절)". 승인 전에는 구현이 시작되지 않는다.
- **프리뷰 확인과 사람 확인**: 후보 커밋·이미지, 프리뷰, 두 독립 보고서를 본 뒤 수정을 요청하거나, "사람 확인 필요" 구역에서 사람이 확인하기로 한 AC를 승인·거절한다(거절은 의견 필수). 승인해도 그 AC의 자동 판정은 "미실행"으로 남는다. 대상이 현재 후보와 다르면 승인 버튼이 막힌다.
- **배포 승인**: 현재 배포 대상이 연결되지 않아 버튼이 숨겨져 있다.

### 재생 보는 법

시작 화면의 "실제 기록 재생"에서 기록을 고르면 같은 사무실이 **읽기 전용**으로 열린다. 승인·수정 요청 버튼이 없고 헤더에 "실제 기록 재생 · 읽기 전용"이 붙는다. 실행 화면 아래 "기록 파일"에서 기록을 내보낼 수 있고, 시작 화면에서 가져온 기록은 "서명 없음"으로 구분되며 프리뷰와 승인은 쓰지 않는다.
