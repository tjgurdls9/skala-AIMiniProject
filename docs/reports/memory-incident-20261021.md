# 16GB 장비에서 7B 모델과 Docker를 함께 돌리다 시스템이 멈춘 사건 (R17 근거)

2026-10-21. 개발 확인 중 발생한 사건이며 제품 수용 기록이 아니다. 사실, 원인 추정, 미확인을 구분한다.

## 사실

- 22:13경 모델 비교 실행(`qwen2.5-coder:7b`를 먼저 쓰는 순서)이 시작된 뒤 시스템이 멈췄다. 사용자가 전원 버튼으로 강제 재시작했다: `/Library/Logs/DiagnosticReports/forceReset-full-2026-10-21-222015.0002.diag`(패닉 문자열 `btn_rst`는 전원 버튼 리셋을 뜻함), `ResetCounter-2026-10-21-222017.diag`. 재부팅 기록 22:19. 22:19:23에 `WindowServer` 진단(`WindowServer-2026-10-21-221923.ips`)이 있어 화면 계층이 먼저 멈춘 정황이다.
- 실행 직전 내가 측정한 기준 상태: RAM 16GiB, **스왑 사용 13807MB / 15360MB**, 시스템 여유 메모리 49%. 이 상태를 확인하고도 시작했다(당시 시작 조건이 없었다).
- 동시에 떠 있던 것: 비교용 `ollama serve`(추론 슬롯 1, 최대 상주 모델 1)와 `qwen2.5-coder:7b`(7.6B, Q4_K_M, 4.7GB, `num_ctx` 16384), Docker Desktop(VM 메모리 8.3GB 할당), 작업 하네스가 만드는 컨테이너(각 512MB 한도), 4초마다 `memory_pressure`와 `docker stats`를 호출하는 샘플러, 다른 사용자 세션과 일반 앱(`uptime`상 4 users).
- 같은 장비에서 `qwen3.5:4b`(3.3GB)로 한 이전 실행 여러 번은 멈춤 없이 끝났다.
- 재부팅 후(22:28): 스왑 0, 여유 61%, Docker 데몬 정지, 내 프로세스 없음. `/tmp`의 비교 부분 결과(`/tmp/cmp-*`)는 **유실**됐다(재부팅으로 비워짐).
- 모델 두 개는 이미 내려받아 `runtime-data/models`에 있다(합계 12GB, Git 제외): `qwen2.5-coder:7b`(4.7GB, Apache License 2.0), `deepseek-coder:6.7b`(3.8GB, DeepSeek License Agreement 1.0).

## 원인 추정 (확정 아님)

- 기준 상태에서 이미 스왑이 총량의 약 90%였다. 거기에 7.6B 모델(상주 약 5GB 이상)과 Docker VM, 컨테이너가 더해져 메모리 압박이 한계를 넘고 UI가 응답하지 않았을 가능성이 가장 높다.
- 샘플러의 `docker stats`가 압박 상태의 Docker Desktop에서 오래 걸려 상황을 키웠을 가능성이 있다.

## 미확인

- 어느 프로세스가 메모리를 얼마나 썼는지(실행 중 기록이 유실됨), 멈춤이 메모리 때문인지 다른 원인(GPU/WindowServer 문제 등)인지.
- 깨끗한 상태(스왑 0, 여유 60% 이상)에서도 7B 모델과 Docker가 함께 안전하게 도는지. 이 사건은 그 반대 증거도 찬성 증거도 아니다.
- 사용자 세션의 다른 앱 구성이 어땠는지.

## 대응 (코드 + 테스트로 고정, `backend/tests/test_memory_guard.py` 16개)

- `infra/dev_checks/memory_guard.py`: 여유 15% 미만 또는 스왑 4GB 초과가 연속 2회면 이 실행이 띄운 `ollama serve`와 `lifecycle-` 컨테이너만 종료하고(다른 앱의 컨테이너·프로세스는 건드리지 않음) 실행을 "자원 초과로 중단"으로 기록한다. 측정값을 읽지 못하면 안전하다고 보지 않는다. 시작 조건은 여유 40% 이상 **그리고** 스왑 2GB 미만이다.
- `infra/dev_checks/compare_models.py`: 한 번에 한 모델·한 작업, 시작 전과 모든 작업 전에 시작 조건 확인, 모델 전환 전에 `keep_alive 0`으로 언로드하고 `/api/ps`가 비었는지 확인, 설정은 `OLLAMA_MAX_LOADED_MODELS=1`·`OLLAMA_NUM_PARALLEL=1`. 조건이 안 되면 시작하지 않고 이유를 기록한다.
- 샘플러(`sample_memory.py`)는 감시자 모듈로 대체했다.

## R17에 대한 의미

16GB 장비는 다른 앱이 이미 메모리를 많이 쓰고 있으면 7B 모델과 Docker를 함께 운용하기 어렵다는 증거가 한 건 생겼다. 운용 가능 여부는 깨끗한 기준 상태에서 위 보호 장치를 켠 채로 다시 측정해야 하며, 그 결과가 "함께 운용 불가"여도 그대로 기록한다. 운영 모델 결정은 사용자가 한다.
