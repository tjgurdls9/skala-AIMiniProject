5. 네 구현 순서와 산출물

A. 실행 기반
- 명세 버전·최초/조정 원문·Phase/Sprint/Task·시도·승인·아티팩트·두 검토·이벤트·외부 operation을 영속화한다.
- 명령 버전·중복 ID·승인 digest·권한을 서버에서 검사한다. 대화 저장과 실행 복구를 구분한다.
- SQLite 원장과 짧은 실행 단위로 구현한다. 사용자 중지·재개·재시작·자원/무료 대기를 실제 상태로 연결한다.
- SSE seq·스냅샷 버전·중복 제거·누락 재동기화의 계약을 구현한다. UI용 공개 로그에 비밀·내부 사고 원문을 싣지 마라.

B. 모델·문맥·RAG/MCP
- 제품 모델은 Ollama 로컬 또는 허용된 Qwen/DeepSeek 무료 경로다. 유료 fallback 금지, 기존 OpenAI 키 자동 사용 금지. 무료/청구 차단 미확인 API는 비활성화한다.
- 사용자 장비 M5 CPU10/GPU10·16GB·1TB 기준, 추론 슬롯 1부터. 가중치와 역할별 대화를 구분하고 모든 역할의 history를 공유하지 마라.
- 작업 시작/재개/수정마다 최신 승인 목표·금지 조건·담당 AC·미해결 실패를 직접 제공한다. 최초 원문·정정 이력·구조화 인수인계를 보존하고 오래된 결과의 통합을 막는다.
- RAG는 스택 문서·코드·계약·결정·오류 해결 근거다. 필수 요구사항을 RAG 성공에 맡기지 마라. 한 작은 코퍼스와 역할 ACL부터 구현한다. 200개 패키지를 설치하지 마라.
- MCP Tool/Resource/Prompt를 실제 권한 경계에 연결한다. 임의 shell·호스트 홈·Docker socket·전체 환경변수 접근을 노출하지 마라.

C. 실제 개발·검토·수정
- 작은 템플릿을 실제 읽기/패치/실행할 작업 공간과 도구를 구현한다. 계획을 말하는 것만으로 구현 완료를 선언하지 마라.
- Front/Back 등 독립 작업은 계약 이후 분담하되 같은 파일 충돌은 통합 담당이 해결한다.
- 검증과 보안은 구현 및 서로의 미확정 판정에서 격리한다. 세션·메모리·검색·파일·도구·출력을 실제 제한한다. 공용 운영자 이벤트로 판정이 새지 않게 해라.
- 같은 후보 커밋·이미지에서 두 검토를 수행하고 원본 보고서를 보존한다. 도구 실패/미실행/불명은 PASS가 아니다. 구현자가 AC·보호된 정답을 수정할 수 없게 한다.
- 프리뷰 수정은 구현 Sprint, 범위 변경은 명세 재승인으로 연결한다. 변경 후 관련 판정·승인을 무효화한다.

D. Git·배포·제출 연결
- 검사한 같은 커밋과 이미지 digest를 사용하고 최신 명세·환경·두 보고서·복구 manifest에 묶인 배포 승인 없이는 배포하지 마라.
- push가 자동 배포를 유발하는지 검사한다. 실제 외부 작업은 승인된 저장소·대상과 권한 범위에서만 수행한다.
- 중복 승인/재시작/응답 유실로 외부 작업을 중복하지 않게 operation 원장과 결과 조회를 사용한다.
- 실제 배포 대상·무료 자격이 없으면 미구현/설정 필요를 명시하고 나머지 구현을 진행한다. 가짜 성공으로 채우거나 유료 호스트를 만들지 마라.
- 실제 실행의 키 없는 REPLAY를 지원하되 새로운 LIVE와 구분한다. 합성 예시를 실제 실행 기록이라고 부르지 마라.

6. 반드시 유지할 사용자 정책

첫 테마는 사무실이다. 추가 테마·비교군·Before/After 실험을 먼저 만들지 마라. 초기 전체 시간·수정·재계획 횟수 상한을 두지 마라. 3회 후 강제 PASS나 기본 graph recursion limit을 제품 전체 상한으로 이식하지 마라. 짧은 영속 실행으로 이어가고 사용자 중지·제공사 한도·영구 오류 처리는 유지한다.
