3. 백엔드를 기다리지 않는 구현 방식

Vue 3와 작은 Vite/TypeScript 구성을 제안 기본값으로 쓰되 기존 프론트가 생겼으면 확인 후 재사용해라. 큰 상태 프레임워크·3D 엔진·외부 폰트를 기본으로 추가하지 마라.

현재 Snapshot/Command/Event 스키마로 화면 모델·상태 표시·합성 예시를 먼저 만든다. 예시는 frontend/src/examples/에 두고 실제 네트워크 데이터와 분리한다. fixture는 계약 필드를 지켜라. UI 선택·펼침·필터 같은 로컬 상태는 별도 view state이며 서버 필드를 발명하는 근거가 아니다.

예시 모드는 화면에 반드시 “합성 예시 · 실제 실행 아님”으로 표시해라. 예시 Snapshot의 mode 값만 보고 LIVE 배지를 붙이지 말고 실제 연결 출처를 함께 사용한다. 예시 조작은 외부 승인·배포를 실행하지 않는다. 합성 기록을 실제 REPLAY라고 표시하거나 fake manifest로 진짜 실행 기록을 가장하지 마라.

작은 API/예시 어댑터 경계를 두고 UI는 같은 Snapshot을 소비하게 해라. 실서비스 전체를 흉내 내는 복잡한 mock 백엔드는 만들지 마라. LIVE 오류 시 예시로 자동 전환하지 마라.

HTTP 생성/runtime/오류/명령 접수/SSE 최초 cursor 등 계약이 미확정인 부분은 Codex 인계를 확인하고 그 연결만 보류해라. 필드를 추측해 계약을 바꾸거나 임시 응답을 실서버 규격으로 굳히지 마라. 지도·작업 상세·사무실·승인 대상 표시·접근성은 계속 구현할 수 있다.

4. 반드시 구현할 화면과 행동

A. 전체 구조
- 요청 입력, 환경 준비/무료 공급자 상태, 최신 명세 버전, LIVE/실제 REPLAY/합성 예시 구분, 항상 보이는 중지.

- 현재 Sprint 목표·작업 의존/대기 이유·AC 현황·근거 패널·시간순 사건 기록. 작업 수 진행과 AC 충족을 구분하고 임의 완료율/예상 시간을 만들지 마라.

B. 사무실 장면
- 명세 회의실→구현 구역→분리된 검증실/보안실→출시 게이트라는 업무 구조를 일관된 2D Canvas로 표현한다.
- Signal_room의 역할별 캐릭터·근거 전달·활동 선택을 참고하되 고정 4인 코드를 그대로 확대하지 마라.
- 서버의 공개 사건과 Snapshot만 실제 상태를 정한다. 움직임·유휴 동작·문서 전달로 성공을 미리 연출하지 마라.
- 모션은 브라우저에서 처리하고 프레임마다 모델 호출하지 않는다. 보이지 않는 화면/모션 감소에서는 렌더링을 줄인다. 느려져도 DOM 조작은 유지한다.

C. 기획·프리뷰·배포
- 기획: 목표·기능·비범위·AC·스택·허용 저장소/배포 환경·무료 정책·변경점을 확인하고 명시 승인/수정 요청.
- 프리뷰: 후보 커밋·두 검토 결과·근거를 보고 구현 수정 또는 기획 변경 피드백. 입력 피드백을 재접속 때문에 잃지 않게 한다.
- 배포: 커밋·이미지 digest·환경·두 보고서·복구 계획이 묶인 승인 대상을 표시하고 서버가 준 digest를 그대로 보낸다. 클라이언트가 승인 해시·판정을 만들지 마라.
- 202는 접수다. 클릭만으로 승인·배포 완료를 표시하지 말고 후속 상태를 확인한다. 중복 클릭·stale approval·409에서 원문 피드백을 보존하고 최신 대상을 다시 읽게 한다.
- REPLAY는 읽기 전용이며 새 실행은 명시적으로 생성한다. 외부 미리보기는 제한 iframe/별도 origin으로 열고 부모 앱 토큰·스토리지 접근을 허용하지 마라.

D. 연결·실패 상태
- 빈 상태·진행·부분 결과·실패·미실행·승인 대기·키/모델/실행기 없음·무료 소진·자원 대기·연결 끊김·중지 처리·완료를 구분한다.
- SSE 중복 제거·끊김·누락 재동기화는 확정 계약대로 연결한다. heartbeat를 진행으로 취급하거나 연결 실패를 작업 실패로 단정하지 마라.
- 재연결/작업 추가로 선택·필터·스크롤·폼을 초기화하지 마라. 서버 검증 없이 UI만으로 안전을 보장한다고 주장하지 마라.

E. 보조 관련도와 접근성
- Jev 아이디어는 관심 분야별 사건 강조·자료 추천·중복 묶기에 쓴다. 우선 기존 태그·작업 의존성으로 동작하고 필요하면 Codex의 로컬 관련도 결과를 소비한다.
- 실제 Jev API/무료 로컬 가중치는 확인되지 않았다. 임의 설치·유료 호출·E5 모델 추가를 하지 말고 “로컬 관련도 보조”처럼 실제 구현을 표시한다. 관련도는 승인·보안·AC 판정을 바꾸지 않는다.
- 실패·보안 차단·무료 소진·승인 대기는 점수와 무관하게 노출한다. 버튼 아래 카드가 갑자기 재정렬되지 않게 한다.
- Canvas와 동등한 DOM 목록·키보드 조작·포커스 이동/복귀·모션 감소·색 이외 상태 표식·읽을 수 있는 대비·모바일 터치 영역을 제공한다.
- 1440/1024/390px를 확인 목표로 한다. dark/light와 office 테마를 구분하고 표시 전환으로 실행/명세/승인/선택을 초기화하지 마라. 미래형·중세·오케스트라·소설 테마는 이번에 구현하지 마라.

6. 정책과 완료 기준

제품 모델/API는 무료 전용이고 OpenAI 키가 존재해도 호출 허가는 아니다. 브라우저에 secret을 넣지 말고 프론트에서 생성/판단 모델 API를 직접 호출하지 마라. 부하는 사무실 장면과 모델 추론을 나눠 관리한다. 비교군과 Before/After는 후순위다. 초기 전체 시간·수정·재계획 횟수 제한을 UI나 로컬 상태에 숨겨 넣지 마라.

완료는 읽을 수 있는 실제 업무 흐름·독립된 두 검토 상태·승인 대상·수정·중지/재개·실패/재접속·접근 가능한 사무실 화면과 실제 API 소비로 판단한다. 합성 예시 단계와 실제 API 연결 완료를 구분해 보고한다.
